# Haruhi 设置页 Tabs

## 目标与依据

将用户图 1 中纵向堆叠的设置区块改为 Tabs。参考 https://coss.com/ui/r/p-tabs-6.json 的图标加文字页签；按用户图 2，将导航放在统一设置卡片顶部左侧，内容在导航下方。

## 布局与交互

- 三个页签：偏好设置、自定义链接、标签管理，分别使用 SlidersHorizontal、Link、Tags 图标。
- 默认显示偏好设置；同一时刻只显示一个面板。
- 页签使用浅灰圆角底轨、白色选中背景和滑动指示器，延续 Haruhi 的中性色。
- 外层卡片统一提供边框、阴影和内边距，面板自身不再重复显示卡片边框。
- 三个面板均不再重复显示页签标题。页签与内容间距为小屏幕 24px、桌面 32px。
- 自定义链接页签激活时，在顶部导航栏右侧显示导入导出按钮；小屏幕按钮换行靠右排列，与页签间距为 12px。导入导出逻辑抽到 `CustomLinksTransfer`，继续共享同一份偏好数据。
- 小屏幕导航等宽排列，文字允许换行；链接新增表单在小屏幕改为单列。
- 方向键和 Home/End 移动焦点并自动切换页签。
- 保留所有面板挂载，切换不丢失链接输入、重命名编辑和未保存的偏好。

## 组件与数据

新增 `components/ui/tabs.tsx`，基于 coss 示例使用 `@base-ui/react/tabs`，由库提供 ARIA、焦点和键盘行为。`SettingsPage` 负责导航和外层卡片；三个现有配置组件负责各自面板内容。继续使用同一个 `usePreferences`，不修改存储格式、导入导出格式或保存时机。

## 验证

运行 Haruhi 生产构建。在临时 Chromium 扩展环境验证默认页签、点击切换、方向键及 Home/End、面板互斥显示、编辑状态保留、跨面板共享数据、保存后重新加载、链接导入导出和手机宽度。截图检查导航位置与选中态。构建和运行失败时先定位原因。
